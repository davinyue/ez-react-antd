# 升级项目依赖到最新版本

## 背景

当前项目依赖升级时出现 npm peer dependency 解析冲突，主要集中在 Vite、@vitejs/plugin-react、Storybook、Vitest 等构建测试工具链版本窗口不一致。

## 目标

将 `package.json` 中的依赖声明升级到 npm 当前 latest 版本，并排查安装、peer 依赖、类型检查、测试和构建兼容性。

## 范围

本次处理 `peerDependencies`、`devDependencies` 的版本声明，重新生成 `package-lock.json`，并执行与依赖升级直接相关的验证。

## 非目标

不主动重构业务代码，不处理与依赖升级无关的现有源码改动，不发布包。

## 关键设计

使用 npm registry 的 latest 版本作为升级目标。安装阶段优先保持 npm 默认 peer 解析规则，不使用 `--force` 或 `--legacy-peer-deps` 掩盖冲突。若验证暴露兼容问题，先定位根因，再做最小必要调整。

## 验收标准

- `package.json` 中依赖声明已升级到 latest 版本。
- 生成新的 `package-lock.json`。
- `npm install` 可在默认 peer 解析规则下完成。
- 完成最小必要兼容性验证，并记录结果。

## 当前进度

已完成依赖升级和兼容性排查。`package.json` 已升级到 npm latest 版本声明，`eslint` 因 `eslint-plugin-react@7.37.5` 尚不支持 ESLint 10，收敛到 ESLint 9 最新兼容版本 `^9.39.4`。已生成 `package-lock.json`，但该文件当前被 `.gitignore` 忽略。

已修复 Ant Design 6、React 19、Vite 8、Vitest 4.1 带来的最小兼容问题，包括类型导入路径、React ref 类型、Drawer onClose 类型、测试环境 ResizeObserver mock、Upload 删除按钮测试查询方式，以及 RemoteTable Less 中 Vite 8 会提示的无效 `:global` 写法。

Ant Design 6 废弃 API 排查命中以下源码迁移项：

- `AdminLayout/HeaderMenu`：`Dropdown.overlayClassName` 迁移为 `Dropdown.classNames.root`
- `RemoteTable`：`Table.pagination.position` 迁移为 `Table.pagination.placement`
- `RemoteTable`：`Divider.type` 迁移为 `Divider.orientation`
- `Drawer`：对外兼容 `width`、`height`、`maskClosable`，内部转换为 Ant Design 6 推荐的 `size`、`mask.closable` 后再传入 Antd Drawer
- `ErrorNotification`：更新注释示例中的 `notification.error({ message })`，避免继续引导使用废弃写法

已完成上述迁移，并补充测试覆盖 `Dropdown.classNames.root`、`Table.pagination.placement`、`Divider.orientation` 以及 Drawer 兼容属性到 Ant Design 6 新属性的内部转换。

验证结果：

- `npm install`：通过
- `npm ls @vitejs/plugin-react vite @types/react @types/react-dom react react-dom antd typescript storybook vitest eslint eslint-plugin-react --depth=0`：通过
- `npm run type-check`：通过
- `npm test -- --run`：通过，4 个测试文件、48 个用例通过
- `npm run build`：通过
- `npm run lint`：ESLint 9 配置入口已兼容，但代码库存在既有 lint 规则错误，未在本次依赖升级中批量修复

补充处理 Vite 8 构建警告：`vite-plugin-dts` 生成声明文件耗时占比较高会触发 Rolldown `PLUGIN_TIMINGS` 提示。该耗时来自组件库正常生成 `.d.ts` 文件流程，不属于构建错误；已将构建配置从已废弃的 `rollupOptions` 迁移到 `rolldownOptions`，并关闭 `checks.pluginTimings`，避免编译阶段输出该提示。

补充调整基础库发布配置：当前构建产物只保留 ESM，不再声明不存在的 UMD/CJS 入口；`package.json` 增加 `type: "module"`，`main`、`module`、`exports.import` 统一指向 `dist/ez-react-antd.es.js`。由于组件库产物包含 CSS，`sideEffects` 改为保留 CSS 副作用。`peerDependencies` 中 React 放宽为 `>=18 <20`，Ant Design 放宽为 `>=6 <7`，React Redux 放宽为 `>=9 <10`，React Router 放宽为 `>=7 <8`，以适配对应主版本消费场景。`vite-plugin-dts` 排除测试、Storybook 与测试环境 setup 文件，避免发布包携带非运行时 API 的声明文件。Grid 相关 resize 防抖类型由 `NodeJS.Timeout` 改为 `ReturnType<typeof setTimeout>`，避免浏览器组件声明文件依赖 NodeJS 命名空间。

补充修复宿主项目从 npm 安装后启动时报 `Calling require for "react"` 的问题：根因是库构建只 external 了 peer 包名本身，没有 external `react/jsx-runtime` 这类 peer 子路径，导致 Rolldown 将 React JSX runtime 的 CJS 片段打入 ESM 产物并在浏览器环境触发 `require("react")`。已将 Vite external 配置调整为函数形式，匹配 peer 包名及其所有子路径。

由于 `0.2.7` 已发布且存在上述运行时问题，包版本提升到 `0.2.8` 用于重新发布修复版本。

补充处理 `vite-plugin-dts@5` 配置迁移：插件声明输出目录配置由 `outDir` 调整为 `outDirs`，避免 IDE 或独立类型检查 `vite.config.ts` 时报 `outDir` 不是有效配置项。
